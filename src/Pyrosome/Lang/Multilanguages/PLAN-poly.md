# Polymorphic multilanguage: plan (branch `multilanguages-poly`)

Goal: generalize the pipeline in this folder so that the *typed side of the
source* is polymorphic (System F fragment: `poly` = All/Lam/@), and generalize
the results.  Pipeline:

```
poly source (typed side polymorphic, boundaries incl. forall rules)
   --[boundary compiler: dtt/ttd -> typerec]-->
poly target (polymorphic, typerec, no boundaries)
   --[mono: monomorphization = type-level partial evaluation]-->
poly target term with no type abstraction/application left
   --[elim_typerec: existing partial evaluator]-->
typerec-free target
```

## Design decisions (fixed; do not re-litigate)

1. **Do not modify existing files** in this folder (their builds take 1-2 h).
   All new work goes into new files that `Require` the existing ones.
   (`PolyBoundaries.v` keeps its old `poly_boundaries`; the new
   value-restricted forall rules get a new name.  Cleanup is a final step.)
2. **Forall boundary rules are value-restricted** (CBV soundness: the old
   `dtt (All A) e = ret (Lam (dtt A e[ty_wkn]))` delays evaluation of `e`
   and is not preserved by the compiler):
   - `"dtt forall"`: `dtt (All A) (ret v) = ret (Lam (dtt A (ret (val_ty_subst ty_wkn v))))`
     with `v : val D G *`.
   - `"ttd forall"`: `ttd (All A) (ret v) = ttd (ty_subst (ty_snoc ty_id *) A) (@ (ret v) *)`
     with `v : val D G (All A)`.
3. **The All case of typerec is boundary-specific.**  A generic 4th case is not
   expressible (its recursive result lives under a type binder, at
   `ty_ext D`, while the case must produce a value at `D`; only higher-kinded
   type variables could abstract that).  So the target gets:
   - a constant `bAll A c` in the style of `bfunc` (explicit arguments):
     `D : ty_env, G : env D, A : ty (ty_ext D), c : val (ty_ext D) (env_ty_subst ty_wkn G) (P A)`
     `|- bAll A c : val D G (P (All A))`
     with rules `"val_subst bAll"`, `"ty_subst bAll"`, `"bAll def"` where
     ```
     bAll def:  bAll A c = pair_val
        (lambda (All A) (let (@ (ret hd) *) (app (.1 (ret (val_subst (cmp wkn wkn) (val_ty_subst (ty_snoc ty_id *) c)))) (ret hd))))
        (lambda *       (ret (Lam (app (.2 (ret (val_subst wkn c))) (ret hd)))))
     ```
     (first component: `-> (All A) *`, instantiate at `*` then coerce at
     `A[*]`; second: `-> * (All A)`, type-abstract then coerce at `A`.
     The `let` in the first component is what makes `"ttd forall"` provable
     with the let-binding compiler.)
   - a rule `"typerec All"` specific to the boundary recursor:
     `typerec (All A) boundary_sigma bstar bbool (bfunc tva tvb (ovar 1) (ovar 0))
        = bAll A (typerec A boundary_sigma bstar bbool (bfunc tva tvb (ovar 1) (ovar 0)))`
     (inner typerec at `ty_ext D`, env `env_ty_subst ty_wkn G`).
4. **`poly` lacks type-substitution laws for `Lam` and `@`** (PolySubst.v has
   `poly_subst_laws_def` as a TODO).  The target extension adds them
   (`"ty_subst Lam"`, `"ty_subst @"`), generated by the same machinery as
   the other `*_ty_subst` languages if possible, otherwise written by hand:
   - `val_ty_subst g (Lam e) = Lam (exp_ty_subst (ty_snoc (ty_cmp ty_wkn g) ty_hd) e)`
   - `exp_ty_subst g (@ e B) = @ (exp_ty_subst g e) (ty_subst g B)`
5. **New target** `poly_target_multilanguage := bAll_cases ++ typerec_All ++ poly_ty_subst ++ target_multilanguage`
   (exact grouping up to the implementer).  Everything old is a suffix, so old
   `eq_term`/`wf_term` facts lift by language monotonicity.
6. **New source** `poly_source_multilanguage := poly_boundaries_v ++ boundaries_ty_subst ++ boundaries_parameterized ++ polymorphic_interoperating_langs`.
7. **Compiler**: `poly_multilang_compiler` (unchanged cases) over prefix
   `polymorphic_interoperating_langs_compiler`, source
   `poly_boundaries_v ++ boundaries_ty_subst ++ boundaries_parameterized`,
   target `poly_target_multilanguage`.  New per-equation lemmas: the two
   `boundaries_ty_subst` equations and the two forall equations, each by
   `by_reduction_fwd` (possibly in hops via `eq_term_trans`, as for `func`).
8. **Monomorphization** is a *generic, rule-driven, reflectively-validated
   rewriting engine* (`Theory/RigidRewrite.v`): given a language and a list
   of equation names whose LHS patterns pass a boolean rigidity check
   (PatternRigidity.v `check_args` + root fit + all ctx vars occur in the LHS),
   bottom-up rewriting with `Matches.matches` is sound (`eq_term`) and
   preserves `wf_term`.  `mono` instantiates it on `poly_target_multilanguage`
   with: `"Lam-beta"`, every `"ty_subst *"` rule (push type substitutions
   through every constructor, incl. typerec/bstar/bbool/bfunc/bAll/Lam/@/let/prod),
   the `ty_subst_lang`/`env_ty_subst`/`sub_ty_subst` action laws (`ty_id`,
   `ty_cmp`, `ty_snoc`/`ty_hd`/`ty_wkn` laws), and `"ty_subst All"`,
   `"ty_subst ->"` etc.  Iterated with fuel.
9. **Completeness of monomorphization is a decidable side condition, not a
   theorem** (System F is not monomorphizable in general).  The pipeline
   theorem is: for `e` wf in the poly source,
   `compile e ≡ mono (compile e)` (poly target), `mono (compile e)` is wf, and
   *if* `all_typerecs_simple_b (mono (compile e)) = true` (and it mentions no
   `bAll`), then `elim_typerec (mono (compile e))` is equal to it and wf in the
   typerec-free target.  Reuse TyperecPartialEval.v's theorems (stated over
   `target_multilanguage`) via a generic "wf transfers down to a sublanguage
   when the term uses none of the extension's constructors" lemma
   (generalizing `no_typerec_transfer`, put in Theory/Conservativity.v) plus
   the stratum check.
10. Concrete examples (vm_compute) showing the pipeline eliminate typerec on
    a program that uses polymorphism, and the check failing on one that
    exports a polymorphic function.

## Build rules

- One heavy Coq process at a time (7 GB RAM).  Build with
  `touch /root/pyrosome-ai/.Makefile.coq.d && make -f Makefile.coq /root/pyrosome-ai/src/Pyrosome/<path>.vo`
  from `/root/pyrosome-ai`.  New files: regenerate `Makefile.coq` first
  (`rm -f _CoqProject Makefile.coq Makefile.coq.conf && make Makefile.coq`),
  hmm — check `_CoqProject` generation; if the project lists files by glob it
  is enough to regenerate.
- Foreground builds die at 10 min; detach long builds
  (`setsid nohup bash -c '...; echo EXIT:$?' > log 2>&1 < /dev/null &`) and poll.
